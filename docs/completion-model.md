# 完成度模型 v3（掌握度设计）

> 2026-08-29 定稿 · 对应 [architecture-decisions.md](./architecture-decisions.md) 阶段 0 的 0.1/0.2
> 目标：把"科目完成度"从"拍脑袋 percent"升级为"**自评 + 对话校准 + 保守处理**"的掌握度模型。

## 一、问题（为什么 percent 不够严谨）

1. **各科口径不同**：数学 60% 和英语 60% 不是一个意思（数学 60%=基础轮快完，政治 60%=强化早期）
2. **百分比是拍脑袋**：55% 和 60% 无可分辨区别，是"感觉"不是"状态"
3. **表达不了状态**："教材过完没做题"算 60% 还是 30%？
4. **自评系统性高估**：尤其初学者（邓宁-克鲁格效应），接近 100% 是理想态，不该轻易采信

## 二、模型 v3 定稿

### 每科学习状态

```
{
  stage: 未开始|学习中|基础完成|强化中|冲刺/掌握,  // 自评档位（"意愿/假设"，非事实）
  confidence: 低|中|高,                            // 是否已被对话校准过
  calibratedStage?,                                // 对话探测后校准档位（有则用它）
  lastProbeAt?,                                    // 上次探测时间
  percent?,                                        // 兼容保留：档位派生，可微调
}
```

**有效档位 = 校准档位（若有）否则 自评档位**。阶段推导、计划生成、完成度显示全部用有效档位。

### 五档（自评友好）

| 档位 | 含义 | 默认映射 percent |
|---|---|---|
| 未开始 | 还没接触 | 0 |
| 学习中 | 正在过教材/跟课 | 40 |
| **基础完成** | 一轮过完（教材+基础习题），可进强化 | 70 |
| 强化中 | 专题/真题训练 | 85 |
| 冲刺/掌握 | 模考/查漏 | 95 |

### 科目感知完成标准（SUBJECT_COMPLETION_GUIDE）

| 科目类 | "基础完成"的认知含义 |
|---|---|
| 数学（数一/二/三） | 高数+线代+概率 教材 + 一轮基础习题过完 |
| 英语（英一/二） | 核心词汇过完 + 语法系统学过（词汇贯穿全程） |
| 政治 | 强化课过一遍（政治通常 7 月后才启动） |
| 408/统考专业课 | 指定教材 + 课后题过完一轮 |
| 自主命题专业课 | 章节过完 + AI 辅助评估 |

### 保守原则（软门控）

- **自评档位 = 假设**，标记"待确认"，不直接采信为"已完成"
- 接近满分 → 温和质疑 + 触发探测（"接近满分很少见，让我确认一下你的掌握度"）
- 档位映射取**下限**：自评"基础完成" → 有效按"待确认"，不立即切强化
- **软门控**：不确认 → 计划不切强化（建议性提示 + 安排基础巩固），但**不硬拦用户前进**（备考管理工具不是考试）
- 计划生成 prompt 明确：**对用户自评持保守态度，优先按基础未完成安排，除非探测证实**

### 对话式校准（探测）

- **形式**：AI 就该科目当前阶段的关键知识点问 2-3 个问题（对话式，非试卷选择题）
- **评估**：不判分、不打脸、给建设性反馈，返回 `{ 校准档位, 依据, 建议 }`
- **触发**：升档标"待确认" + **计划生成前统一确认一次**（推荐）｜用户主动
- **复用**：chat 的 `callAI`；测评消抵触原则（低压力 / 测试即学习 / 蒙对标记同源）
- 范围：先做数学/英语两科目，其余科目先只自评，避免摊太大

### 遗忘衰减（decay，阶段 1）

- 隔久未学的科目标记"需巩固"（沿用已有 SM-2 的遗忘思想）

### 先测后分班（长线期/探索期，阶段 1）

- 新用户不信任初始自评 → 首次对话摸底建立基线，再定初始档位

## 三、市场借鉴（2026）

| 产品 | 机制 | 我们学什么 |
|---|---|---|
| **Anki/SM-2** | 四键自评 + ease factor 衰减校准（"Easy"点多不降频） | 自评当假设、用行为校准；已有 SM-2，扩展思想 |
| **Math Academy** | 掌握度硬门控（不证明不前进）+ 陷阱题 | 学"软门控"版；我们是管理工具不能硬卡 |
| **Duolingo** | 入学分班测 + 弱项 decay | 先测后分班、掌握会遗忘要修复 |
| **Khan Academy** | 档位化掌握度，只认做题表现 | 五档思路验证 |
| **Brilliant.org** | 对话式/交互式逐步探测理解 | 对话式测验形式被市场接受 |

2026 现状：Math Academy AI 一对一、YC 孵化 Bloomy（K-12 AI mastery）、学而思联合信通院立 AI 教育标准——**"掌握度必须验证、AI 校准学情"已是行业共识方向**。

## 四、边界（诚实声明）

- 上述产品多有**自己的内容 + 题库** → 能做"**考核型掌握度**"（必须答对题库才算掌握）
- 我们是备考管理工具，**无内容** → 只能做"**校准型掌握度**"（自评 + 对话 + 保守）
- 校准型对管理工具**足够且诚实**；内容级深度验证是内容产品的活

## 五、阶段 0 实施范围

- **0.1 完成度模型落库 + 迁移**：档位字段（additive 到现有 `Goal.progress` Json，不推倒）+ 科目标准表 + 保守映射 + 老数据档位推断
- **0.2 对话式校准**：探测形态待定（见待决）
- **0.3 阶段推导 + 文案**：`derivePrepStage({ examDate, hasGoal, 各科有效档位, studyLoad })` → 四段（探索/基础/备考/冲刺）
- **0.4 计划类型确认流 + 课业标记**：探索期可生成计划（AI 判断类型 + 生成前告知）；`Goal.studyLoad Json?` UI

## 六、待决

1. 探测形态：内嵌小对话 vs **计划生成前批量确认**（推荐后者：升档只标"待确认"，计划生成前统一确认一次，更不打扰）
2. 切割：先做"自评 + 对话校准 + 保守软门控"三件；decay / 先测后分班放阶段 1（推荐）
