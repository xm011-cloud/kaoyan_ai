# 阶段 0：反馈台账与首屏主线审计

## 1. 目标

将“资源和错题不好用、首页不知道做什么”的笼统反馈变成可复现问题。完成后，团队能依据三类用户的真实路径判断哪些是阻断、哪些是理解成本，且不以新增功能掩盖问题。

## 2. 范围

- [x] 建立 [反馈台账](../feedback-backlog.md) 与严重级别规则。
- [x] 根据现有用户反馈和代码结构建立 6 条初始待复现问题。
- [ ] 执行新手、正常用户、积累用户各一条主路径走查；优先手机，桌面用于复核布局差异。
- [ ] 为每条确认问题补充截图/录屏、实际结果与复现状态。
- [ ] 对首页首屏作出“保留、下沉、隐藏”的收缩决策。

## 3. 非目标

- 不在本任务中重构首页、课程、资料或错题页面。
- 不新增资源表、公共题库、视频托管或 AI 功能。
- 不把自动化通过视为真实用户理解的证据。

## 4. 验收条件

- [ ] P-A 新手可完成“首页 → 首周探索 → 第一项任务 → 留下一句理解 → 回首页”。
- [ ] P-B 正常用户可完成“首页 → 今日任务 → 课程/练习 → 结束学习 → 回首页”。
- [ ] P-C 积累用户可完成“首页 → 今日复盘 → 连续复习 → 留下策略 → 知识点回看 → 原题”。
- [ ] 每条 P0/P1 均有可复现步骤、证据和责任阶段；未确认的问题保留为“待复现”。
- [ ] 首页首屏收缩决策记录在台账，且没有未处理 P0。

## 5. 测试范围

### 自动化检查

- [ ] `dashboard.spec.ts`、`courses.spec.ts`、`wrong-questions.spec.ts` 基线。
- [ ] 必要时为确认后的 P0/P1 增加回归用例。

### 手工检查

- [ ] 桌面：1366px 以上宽度。
- [ ] 手机：390px 宽度，包含输入、滚动和返回场景。
- [ ] 使用独立测试数据，不污染真实学习账户。

### 本轮执行原则

- 反馈收件箱已部署，本任务不再建设新的反馈表单、台账或作者后台。
- 自动化只用于回归；三条路径的完成条件是实际操作证据与清晰的产品决策。
- 确认的 P1 直接进入既定阶段：今日主线（阶段 1）、学习资源（阶段 2）、错题复盘（阶段 3）；不因“继续调研”阻塞已有方向。

## 6. 完成记录

- 已完成：台账、反馈收件箱、走查矩阵、初始问题与开发计划同步。
- 未完成：三类用户实际走查、首页收缩决策，以及确认问题的阶段归属。
- 下一步：按 P-A、P-B、P-C 各完成一次主路径并回填台账；若没有 P0，立即进入阶段 1 的“今日唯一主线”。
