# C6 V1 产品与开发计划

> 更新于 2026-09-30。本文记录当前第一版的产品边界、交付顺序和验收标准；已实现功能清单见 [PROJECT_STATUS.md](../PROJECT_STATUS.md)，长期架构决策见 [architecture-decisions.md](./architecture-decisions.md)。

## 1. 第一版要做什么

### 服务谁

考研刚开始、学习安排混乱，或基础薄弱的学生。他们通常已有课程、资料和常用 AI 工具，却不知道每天先学什么，也无法把课程、错题和笔记沉淀成持续可用的理解。

### 一句话定位

**一个把“今天行动、长期阶段与个人理解”串成闭环的考研学习导航与知识沉淀系统。**

用户每天打开 C6，应该能立刻回答四件事：

1. 我今天先做什么；
2. 这件事在推进哪个阶段和里程碑；
3. 做完后我该留下什么理解或证据；
4. 我目前真正卡在哪里，下一步该怎么调整。

### 非定位

- 不是课程内容平台，不托管或转发第三方网课；
- 不是通用 AI 聊天客户端；
- 不是完整笔记软件、网盘或百科；
- 不是社区、学习小组或自由拖拽画布产品。

## 2. V1 的核心闭环

```text
首周探索（方向 + 薄弱科目 + 可投入时间）
  → 学习档案 / 目标
  → 阶段路线与里程碑
  → 本周方向与今日下一步
  → 课程学习 / 练习 / 错题复习
  → 学习证据 + 我的理解与方法卡
  → 复盘确认与安全调整
  → 下一周计划
```

计划是主引擎；课程、练习和错题是执行场景；知识系统负责保存用户自己的理解、易错点和解题思路；AI 只在需要判断、整理和调整时充当学习管家。

## 3. 双层知识系统

### 3.1 系统学科骨架（知识点知识图库）

系统维护、版本化且可审核的学科目录、章节和前置依赖。它回答“该学什么、它和什么有关”，不能由模型在用户使用时随意生成或改写。

第一版的默认呈现是科目 → 章节 → 知识点的可展开地图，并在单一章节内显示局部前置/后续关系；不把全科力导向大图作为默认入口。

每个节点至少包含：名称、科目/章节、前置节点、后续节点、在路线中的阶段归属和用户学习证据摘要。学科骨架的首批覆盖范围须按真实目标用户和可审核内容确定，不能为“全科齐全”牺牲正确性。

### 3.2 个人认知层（我的理解与方法卡）

用户沉淀的不是教材复述，而是：

- 我用自己的话如何理解；
- 我曾经混淆或容易错在哪里；
- 遇到某类题时应如何切入、检验和推导；
- 它与哪节课、任务、错题和相邻知识有关。

一张卡片的最小字段为：知识点、用户原话、卡片类型（理解 / 易错点 / 解题策略 / 关联线索）、来源、关联节点、掌握自评和下次回顾时间。AI 可以从用户输入中提取候选结构，用户确认后才写入。

### 3.3 两层如何联动

- 课程、任务完成和错题复盘都可创建同一种个人卡，并自动带入来源；
- 每张个人卡归属一个或多个系统知识节点，避免变成孤立笔记；
- 知识节点页展示用户的理解卡、关联错题、课程记录、待复习内容和掌握证据；
- 多次“模糊/不会”或关联错题增长，只能触发复盘与补强建议，不能自动宣称掌握或完成里程碑；
- 计划任务关联知识节点，复习到期卡和薄弱节点可以成为下周计划草稿的输入。

## 4. V1 功能边界

### 必须交付

| 能力 | V1 用户价值 | 完成标准 |
|---|---|---|
| 学习档案与目标 | 从不完整方向开始，而非逼迫用户一次填全 | 目标可暂定，容量、基础和目标不确定项可逐步补全 |
| 阶段路线与计划 | 看到阶段、退出标准、里程碑、本周方向和今日下一步的关系 | 任一任务可追溯到里程碑；调整前可见影响 |
| 今日学习入口 | 一打开就知道现在做什么 | 两步内进入实际任务、课程、练习或复习对象 |
| 课程学习记录 | 记录真实学习、笔记和自评，不接管第三方课程 | 可从任务直达课程/外链，学习会话形成证据 |
| 最小练习与错题闭环 | 薄弱点进入复习和计划，而非停在错题本 | 错题能关联知识点/理解卡，并可形成补强建议 |
| 个人理解与方法卡 | 把理解、易错点、策略留下并能再用 | 从课程、任务、错题创建；按到期时间主动回顾 |
| 知识点知识地图 | 给个人卡、计划和错题一个共同骨架 | 科目树、节点详情、局部关系、关联学习证据可用 |
| AI 学习管家 | 规划、复盘、整理和调整，而非无边界聊天 | 先澄清目标/基础/容量；输出可确认草案与影响说明 |
| 三端可用性 | 手机也能执行每日闭环 | 手机不遮挡输入与主操作，AI 以全屏工作区出现 |

### AI 的明确取舍

- 保留：路线/周计划草案、每日复盘、调整影响分析、笔记转理解卡候选、知识点关联建议；
- 降级：即时题解、连续闲聊、临时出题和泛资料问答；
- 对即时问答，优先提供带课程/题目上下文的复制提问模板或外部 AI 打开入口，让用户继续使用自己信任的工具；
- 所有 AI 写入操作都必须有明确预览、确认和失败恢复；没有可靠证据时不得判定用户已掌握。

### 暂缓，不纳入 V1 验收

- 站内视频托管、下载、转码、字幕与第三方播放器进度控制；
- 社区、小组讨论、排行榜强化和多人协作；
- 任意拖拽/缩放的插件化工作台；
- 完整白板、手写笔记、第二套文档编辑器；
- 大规模资料 OCR、复杂 RAG、自动读完整网课；
- 全科力导向知识网络、自动生成全量学科关系；
- 高频 AI 闲聊、自动题解和自动出题；
- 院校信息、技能市场等低频功能的继续扩展。

## 5. 接下来按顺序交付什么

### 当前进度（2026-09-21）

- P0 已收束到可用状态：计划页优先呈现正式路线阶段、本周推进的里程碑与执行画布；低频的科目自评按需展开。后续只修复闭环断点，不再重做计划页面外观。
- P0.5 已落地：首次进入首页的用户可用“方向、当前最想补的一科、每周可投入时间”直接开启首周探索。系统只创建 1–3 个可完成的学习样本、探索阶段与里程碑；它不调用 AI、不生成半年计划，也不据此宣称掌握。完成后仍通过已有理解记录和长期路线澄清流程继续。
- P2 已落地：复用 `StudyNote` 作为个人认知记录，课程、任务和错题可保存“我的理解 / 易错点 / 解题思路”；“我的理解与方法”提供统一回看、来源回跳、个人知识点关联和真实回顾节奏。
- P2 回顾已落地：理解卡可按“能复述 / 有点模糊 / 需要重看”记录状态并安排下次回顾；该结果不自动推进任何里程碑。
- P3 已建立底座：系统学科骨架是版本化、只读、人工审核的数据源；首批覆盖 408 计算机网络主干及前置关系。理解记录已具备保存系统节点 ID 的数据接口，下一步接通用户确认式选择和节点证据视图。
- 当前风险：现有私人 `KnowledgeNode`（用户自己建的点）与系统课程骨架仍是两套来源。第一版让它们在同一张理解卡上并存、互相引用；不仓促合并表结构，也不自动猜测映射。

### R1：理解卡 → 系统知识节点的人工确认关联

**状态：实现完成；核心关联链路已由 API/E2E 覆盖，完整套件回归归入 R5 发布门槛。**

**要做**：用户在“我的理解与方法”展开已审核的科目骨架后，可为卡片选择一个或多个系统节点；卡片显示节点名称，并能进入对应局部路径。课程、任务、错题创建理解卡时可以带入候选节点，但必须由用户确认保存。

**不做**：按文本、科目或 AI 自动把旧笔记归类；为所有科目补齐骨架。

**验收**：用户能在一分钟内把一条“TCP 三次握手容易混淆”的记录关联到“TCP 连接管理”，之后从卡片回到该节点并看见其前置关系。

### R2：系统节点的学习证据视图

**状态：实现完成；节点详情、证据回读与手机布局已有针对性验证，完整套件回归归入 R5 发布门槛。**

**要做**：为系统知识节点建立轻量详情视图，汇总显式关联的个人理解卡、相关错题/练习、学习任务和待回顾状态；展示事实与建议，不显示虚假的总掌握度。

**依赖**：R1 的人工关联。计划任务和错题的关联先采用显式字段或用户选择，不能根据标题猜测。

**验收**：用户从理解卡进入节点后，能回答“我学过什么、哪里容易错、下一次该复习什么”。

### R3：路线与节点联动

**状态：实现完成；任务—节点—里程碑的回读已有针对性验证，完整套件回归归入 R5 发布门槛。**

**要做**：给新建/调整计划中的任务增加可选系统节点归属；本周计划和里程碑页显示“本周覆盖哪些节点、哪些节点缺少证据”。调整只重排未完成任务，保留已有理解、错题和学习证据。

**不做**：完成一次任务后自动提高掌握度或自动完成里程碑。

**验收**：任一今日任务可追溯到里程碑和系统节点；任一节点可反向看见本周正在推进它的任务。

### R4：AI 收束为学习管家

**状态：实现完成；AI 约束和提案流程待与完整 AI 路径一并回归。**

**要做**：计划生成先核对目标、基础、容量和阶段退出标准；建议展示阶段目标、周方向、任务—里程碑—节点关系及影响预览。对即时题解提供外部 AI 提问模板或跳转，而不把慢且不稳定的自由问答放在主路径。

**不做**：把模型输出直接写入任务、里程碑、理解卡或系统骨架；继续扩展高频闲聊与自动出题。

**验收**：信息不足时 AI 先提最少的澄清问题；有变更时，用户能看到保留、移动、取消和待确认的部分。

### R5：三端收口与发布门槛

**状态：完成并已发布（2026-09-29）。桌面导航、AI 工作区三端、课程—任务—理解记录—节点详情、周报降级和掌握度复盘的定向 E2E 均已通过；节点只读查询、幂等测试请求和周报 AI 都已增加有限重试或超时兜底。首次引导偶发问题已在发布版本 `0cd4eee` 修复，连续专项回归及全量 Playwright **174/174** 均通过；生产别名已切换，未登录保护及登录后首页、计划、课程、知识、错题页面均已只读验证。写入理解记录并回读节点证据仍使用真实账户抽查，详见 `docs/test-baseline.md`。**

**要做**：逐一验证概览、计划、课程、错题、理解卡、节点详情和 AI 工作区的桌面/平板/手机体验；补齐空状态、失败恢复、加载和键盘避让。为 R1–R4 的主路径增加 API/E2E 覆盖。

**验收**：手机上从“今日任务”到记录理解、关联节点、安排回顾全程不被导航、底栏、AI 或键盘遮挡；核心数据写入后可回读、刷新后不丢失。

### 内容扩展门槛

只有 R1–R5 完成且真实用户连续使用两周后，才补充数学、英语、政治等审核骨架。每增加一个学科，需要同时具备来源说明、版本号、章节结构、前置关系和至少一个节点详情验证样例；不能只导入一张“大而全”的知识图。

## 6. 第一版功能取舍（冻结清单）

| 保留并继续投入 | 仅维护、不扩展 | 明确暂缓 |
|---|---|---|
| 目标、路线、周计划、今日任务 | 院校信息、番茄钟、周报、技能 | 视频托管/下载/转码、社群与排行 |
| 课程外链与学习记录 | 泛资料搜索、低频设置页面 | 自由拖拽工作台、完整白板/手写笔记 |
| 错题复习、个人理解卡、知识节点 | 通用聊天历史 | 全科知识大图、OCR/RAG 重工程 |
| AI 规划、复盘与调整草案 | 现有练习功能 | 高频即时题解、自动出题、自动判定掌握 |

这张表是开发边界，而不是删除现有入口的清单：第二列功能保持可访问和修复，但不消耗当前核心迭代时间。

## 7. 执行原则

1. 每轮只推进闭环中的一个断点，先证明用户能完成动作，再扩展展示能力；
2. 低频配置默认折叠，页面只突出当前决策和下一步；
3. 数据事实、用户判断和 AI 建议始终分开保存；
4. 系统学科骨架可审核、可版本化，个人理解归用户所有；
5. 历史证据和已完成任务不因后续调整被重写；
6. 未完成 R1–R5 的验收前，不以新增低频模块代替核心闭环。

## 8. 下一次开工的具体目标

先对首周启动路径进行真实用户狗粮：记录“首周设置 → 第一项任务 → 理解记录 → 回到首页”的完成率、卡点和任务是否可理解；确认用户不会被错误带入长期路线。随后进入两周闭环狗粮期，记录“今日任务 → 课程/练习 → 理解卡 → 知识节点”的完成率、卡点和计划调整影响；只修复闭环断点。未获得连续两周的真实使用反馈前，不扩展新的学科骨架或暂缓模块。
