> 起于 2026-08-29 · 记录"为什么这样设计"的方向与架构决策，避免反复推倒重来。
> 与 [PROJECT_STATUS.md](./PROJECT_STATUS.md) 的关系：本文档记**方向与接口决策**；PROJECT_STATUS 记**已实现的功能**。

## 一、产品定位（2026-08-29 讨论收敛）

**一句话：给学生的 AI 学习引擎 + 考研适配 —— 内核通用，考研做透，数据从大一攒到上岸。**

- **主战场**：考研人全旅程（长线准备 → 正式备考 → 冲刺 → 二战/在职）
- **内核通用**：计划/打卡/番茄/错题/RAG 资料问答与考试无关，天然通用；自由度高、不锁死考研
- **不做其它考试**：不服务考公/法考等（各考试结构差异大，贪多嚼不烂，稀释考研深度）
- **大一用户**：架构支持通用（降门槛），运营先聚焦考研（有强共性）；是否正式主推大一，**用数据决定**

## 二、核心差异化（回答"为什么不用通用 chatbot"）

- 通用 chatbot：用户要自己把它调教成考研专家，每次重喂上下文，AI 记不住你的计划/错题/进度
- **我们的 AI**：接进一套完整备考数据 + 工具（建任务/收录错题/查资料/出题/评测），**开箱即用**，AI 的每个动作直接写进备考体系
- 技能系统是它的进阶延伸：用户编排"AI 怎么用我的数据"；官方做深核心闭环，长尾需求交给社区

## 三、已定方向

### 3.1 自由度（拉高，不锁死考研）
- 不强制"考研目标"才能用；用户可手动自建计划，也可让 AI 生成非考研的科目计划
- 计划生成入口第一问：「你要为哪件事做计划」→ **计划类型分发**（考研备考 / 课程期末 / 自学单科 / 考证…）
- 这同时服务：方向未定的大三用户、课程学习的大一用户、自学者

### 3.2 测评（消抵触设计）
- **不叫考试**：叫"水平自检 / 现状扫描"；低风险明示（"答对答错不影响任何东西"）、短快即时价值、渐进出现
- **自选讲解三态**：答对且真会 → 可跳过讲解；答对但"蒙的" → 标记后进讲解 + 按"未掌握"处理；答错 → 默认展开讲解
- "蒙对"标记价值：① 提升测评数据质量（蒙对 ≠ 掌握，避免水平/择校判断偏乐观）② 元认知训练
- 测评产出 → 水平 → **择校匹配**（复用 admission 分数线数据）

### 3.3 技能插件化（从"对话工作流" → "数据+逻辑+表现的声明式小应用"）
- **三层**：数据层（白名单快照 + 技能档案 note + 输入）/ 逻辑层（AI 步骤 + 事件→动作）/ 表现层（组件）
- **AI 只是其中一种数据源和逻辑器，不是全部**（背单词不需要 AI 也能成立）
- **两种宿主**：向导流（一次性流程）/ 工具页（可反复使用的页面，如背单词页）
- **组件调色板**：题卡（从 practice 抽象）/ 闪卡 / 数据展示 / 进度 / 按钮 / 表单 + AI 输出渲染
- **能力分级**：官方组件 → 组合组件 → 受限表达式 → 沙盒代码组件（重工程，后置）
- **分享**：技能 = 结构化 JSON 工件，分享 = 详情页 + 一键安装；信任机制复用 admission 经验（多来源 + 点赞/质疑）
- **受限表达式**：能"算"不能"做"的迷你语言（纯函数、无副作用、不访问外部），V2/V3 的进阶能力

### 3.4 激活漏斗页（决策依据，先做）
- **定位**：admin 诊断页，只给开发者看，不是产品功能
- 阶段：注册/激活 → 设目标 → 生成计划 → 首次打卡 → 配 AI → 用过深功能 → 7 日回访
- 形态：阶段转化率 + 单用户轨迹（点开一个卡住的用户看他的使用痕迹）
- 目的：目前所有方向讨论都在猜，先让数据说话

### 3.5 引导（从"解释功能"到"让用户知道他在做什么"）
- 每个最小行动配方向感：**要做什么 / 为什么 / 做完得到什么 / 处在第几步**；跳过永远在
- 首访一句话引导（每页首次进入一条横幅）+ 术语去化（知识图谱→知识点关系图等）
- 阶段性评估：解释功能 < 让用户先做成一件小事

## 四、架构决策（必须现在定，防推倒重来）

| # | 决策 | 内容 | 不定会怎样 |
|---|------|------|-----------|
| **D1** | 技能 JSON schema **版本化** + 可扩展 step 类型 | 为 render/layout（页面组件步骤）留位，保持向后兼容 | 技能系统锁死在"对话流"，长不成"页面应用" |
| **D2** | **组件契约**接口文档 | 输入 / 状态 / 动作 / 渲染 定成接口，官方组件先实现 | 将来开放用户自制组件要推倒 |
| **D3** | Goal **自由度** | `university` / `examDate` 可空，或加轻量"方向"概念 | 上线后再加要数据迁移 |
| **D4** | **计划类型分发**接口 | generate-plan 不写死考研，抽象成"类型注册表 + 分发" | 写死后加通用计划要重构 |
| **D5** | **AI 内容护栏 + 技能能力白名单** | 合规红线前置：能力收紧（白名单数据 + 平台 AI 路由）/ 内容红线（作弊、代考、侵权、违法）/ 社区机制（举报、信任、审核） | 合规事故（尤其代考作弊）代价远超收益 |

**原则**：推倒重来的风险不在"功能没做够"，在"接口和 schema 定得不对"。功能是增量（加字段、加路由），接口错了才要重写。D1–D5 现在定，其余全部可后补。

## 五、七条线程三问评估（能不能做 / 有没有必要做 / 做到什么程度）

| 线程 | 能不能 | 必要性 | 程度 |
|------|--------|--------|------|
| 定位收敛 | 可行，内核已通用 | 必要（方向地基） | 现在决策期；落地只改文案/入口 |
| 激活漏斗页 | 很简单（admin 页 + 聚合查询） | 最必要（决策依据） | 只做阶段转化 + 单用户轨迹 |
| 引导改造 | 容易（前端 + ui-store 标记） | 必要 | 首访一句话先做；场景入口后做 |
| 多阶段/长周期 | 可行，最小版不碰 schema | 必要（考研全旅程核心） | 阶段推导 + 文案/计划跨度分档；完整建模看数据 |
| 自由度计划 | 可行（类型分发抽象） | 必要但**不急** | 意图第一问 + 3 种官方类型；社区贡献别现在做 |
| 测评体系 | 可行，复用 practice/模考 | 必要（"学习产品 vs 管理系统"分水岭） | 自选讲解 + 蒙对标记近期做；水平→择校等阶段化后 |
| 技能插件化 | 能，但分级；沙盒是重工程 | 定位招牌，但近期对用户未必必要（长期投资） | **架构决策现在定，实现做最小**（官方组件 + 工具页宿主） |
