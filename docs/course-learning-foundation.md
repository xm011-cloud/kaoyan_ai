# 课程学习地基（阶段 A / B）

## 产品边界

C6 是个人备考协作系统，不是课程内容平台。它不下载、转存、再分发未经授权的第三方课程；用户可以把已有课程链接、合法访问入口和私有资料关联到自己的学习路径。

## 最小闭环

```text
Course → CourseUnit → CourseLesson → StudySession → StudyNote / 自评 → 后续练习与计划调整
```

- `Course`：用户正在跟的一门课程，记录来源类型但不保存受版权保护的第三方内容。
- `CourseUnit` / `CourseLesson`：用户可理解的章节和课时；AI 后续只能在用户确认的课程结构内给建议，不能凭空编造课程目录。
- `StudySession`：一次真实学习过程。`completed` 只表示本次课时学完；`selfAssessment` 记录当次感受，不能直接作为掌握度事实。
- `StudyNote`：必须关联课时或学习会话，可标记为笔记、重点、疑问、易错点；后续才会关联错题、知识点与复习。

## 计划知识来源

计划不能只来自大模型或通用模板，后续必须同时使用：

1. 考试与目标约束（专业、院校、年份、可投入时间）；
2. 版本化学科路线与知识依赖；
3. 用户确认的课程/资料结构；
4. 用户学习证据（会话、自评、练习、错题、复习）。

模型职责是理解表达、产生草案和解释取舍；批量计划变更仍需影响说明、确认和版本记录。

## 本轮未承诺的能力

- 课程版权采购、自制课程、第三方课程下载或转存；
- 视频上传、转码、字幕、OCR 与后台队列；
- B 站等第三方播放器的精确进度控制；
- 手写画布、完整笔记软件、多 Agent 课堂；
- 课程与任务的自动批量生成。

## 存储原则（上线前必须落地）

- 结构化学习数据放 PostgreSQL；附件放私有对象存储；资料文本按切片建立向量索引。
- 不允许对象存储失败后伪造“可访问附件”；必须向用户明确显示处理状态。
- 上线前设定单文件、总容量、保留期、软删除与彻底删除策略；导出应包含用户可读的学习记录与附件清单。
- OCR、嵌入、转写等长任务进入可靠队列，不在 HTTP 响应结束后以 fire-and-forget 方式依赖执行。
