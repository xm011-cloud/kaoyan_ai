# C6 V1 产品与开发计划

> 更新于 2026-10-23。本文是当前 V1 的开发顺序与验收依据；已实现功能见 [PROJECT_STATUS.md](../PROJECT_STATUS.md)，架构约束见 [architecture-decisions.md](./architecture-decisions.md)，真实使用问题记录在 [usage-notes.md](./usage-notes.md)，阶段 0 台账见 [feedback-backlog.md](./feedback-backlog.md)。

## 1. 第一版要做什么

### 服务谁

考研刚开始、学习安排混乱或基础薄弱的学生。他们通常已有课程、资料和习惯使用的 AI，却不知道每天先做什么，也无法把课程、错题和笔记沉淀成可再用的理解。

### 一句话定位

**一个把“今天行动、长期阶段与个人理解”串成闭环的考研学习导航与知识沉淀系统。**

用户每天打开 C6，应该能立刻回答：

1. 我今天先做什么；
2. 这件事在推进哪个阶段和里程碑；
3. 做完后应留下什么学习证据、理解或方法；
4. 我目前真正卡在哪里，下一步应如何调整。

### 非定位

- 不托管、下载、转码或代理第三方网课；
- 不做通用 AI 聊天客户端，也不要求配置 AI 才能学习；
- 不做完整笔记软件、网盘、公共题库或百科；
- 不做社区、自由拖拽画布、完整白板或手写笔记产品。

## 2. V1 的核心闭环

```text
首周探索（方向 + 薄弱科目 + 可投入时间）
  → 学习档案 / 目标
  → 阶段路线与里程碑
  → 本周方向与今日唯一下一步
  → 课程 / 练习 / 错题复盘
  → 学习证据 + 我的理解、易错点、解题思路
  → 用户复盘确认与安全调整
  → 下一周计划
```

计划是主引擎；课程、练习和错题是执行场景；知识系统保存用户自己的理解、易错点和解题思路；AI 只在规划、整理和调整时作为学习管家。

## 3. 当前基线

截至生产版本 `7b30db0`，以下能力已经存在并经过自动化回归：

- 新用户无需 AI Key 可从首页开启首周探索，建立探索阶段、里程碑、周计划和学习样本；
- `Goal → StudyPath → WeeklyPlan → Task → StudyEvidence` 可追溯；任务完成不等于掌握；
- 首页已有“长期方向 → 当前阶段 → 本周方向 → 今日下一步”，有课时的任务可直达课程学习桌；
- 课程支持外链和 `b23.tv` 短链，可记录学习会话、自评、笔记与下一步；未关联课程的任务可创建课程并自动关联首课；
- 上传附件无论能否解析都有明确反馈；不可检索文件仍可作为学习附件保留；
- 错题已有到期队列、逐题复习、SM-2 排期、幂等证据和历史“易错点 / 解题思路”回带；
- 课程、任务、错题可以创建 `StudyNote`；用户可确认关联知识节点，理解库能精确回到原任务周或原错题；
- AI 可用但不在主流程；路线、计划和调整均使用澄清、草稿、确认边界。
- 产品反馈已可按类型提交、分诊、回看处理状态；它用于收集真实断点，不替代学习路径走查。

当前不能视为完整 V1，原因是：

1. 反馈台账和收件箱已经具备，但尚未完成新手、正常用户、积累用户的三条可复现狗粮路径；
2. 首页、课程、资源与错题的新路径虽已通过自动化回归，但尚未完成新手、正常用户与积累用户的真实走查；
3. 学习资源已聚合课程与附件并展示资源用途，但仍需确认用户是否能在真实资料上自然记录进度、卡点和下一步；
4. 错题复习已隐藏 0–5 算法评分，并支持在写下复盘后主动确认课程知识点；仍需验证该入口在真实复盘中是否自然；
5. 知识库仍偏记录列表，未稳定呈现节点的学习、错误、复习、资源与未解决问题。

## 4. 数据与架构约束

- 保留现有 `Goal`、`StudyPath`、`WeeklyPlan`、`Task`、`Course`、`Material`、`StudySession`、`WrongQuestion`、`StudyNote`、`KnowledgeNode` 与 `StudyEvidence`；不重写历史数据。
- 任务、课程、练习、错题只追加或更新幂等学习证据；只有用户复盘才能改变里程碑结论。
- 用户私有数据继续遵守服务端所有权校验；个人布局偏好只存客户端。
- “资源关联层”先作为现有对象的统一投影实现：课程外链用 `Course / CourseLesson`，附件用 `Material`，个人记录用 `StudyNote`。只有真实反馈证明现有模型无法表达需求时，才评审 `LearningResourceLink` 新表，并先提交迁移与回滚方案。
- AI 可提出候选、解释影响，不能静默写入任务、里程碑或知识关系，也不能断言用户已掌握。

## 5. 开发顺序：阶段 0–4

每阶段只解决一个用户问题。本阶段验收、真实路径验证和发布后观察完成前，不进入下一阶段开发。阶段 0 不再开发新的反馈功能，只做短验收并做出首页收缩决策；验收结束后立即进入阶段 1。

### 阶段 0：可用性排雷与范围收缩

**用户问题**：我们尚未分清哪些流程真的坏了，哪些只是用户看不懂；首页与导航仍可能把用户带离学习主线。

**实现范围**：

1. 反馈台账与反馈收件箱已经完成；不新建问卷、表格或后台能力，只把确认的问题补齐复现证据和修复版本。
2. 用三类路径各走一次：新手（无目标、无 AI、无资料）、正常用户（有计划和课程、刚练习）、积累用户（多任务、错题、理解记录）。桌面和手机共用同一套判定标准。
3. 问题按 P0（阻断、报错、数据错误）、P1（能做但看不懂）、P2（不阻断但别扭）、暂缓分类；若发现 P0，先修复再进入阶段 1；若确认现有 P1，则将其分配给阶段 1、2 或 3。
4. 基于三条路径作出首页收缩决策：首屏只保留阶段、本周方向、今日下一步、今日复习；低频能力进入二级工具区；每个空状态只给一个下一步。

**不做**：视觉大改、卡片定制、低频工具扩展、仅凭接口测试关闭用户问题。

**验收**：

- 新手不配置 AI，能完成“首页 → 首周探索 → 第一项任务”；
- 三类用户各有至少一份可复现记录，所有 P0 都已修复或有明确阻塞说明；
- 首屏不要求理解工作台配置，也不出现多个同级主行动。

**进入阶段 1 条件**：无未处理 P0，三类路径已手工复核，且已记录首页首屏的“保留 / 下沉 / 隐藏”决策。

### 阶段 1：把今日学习做成唯一主线

**用户问题**：用户打开 C6 后仍可能只看到信息，不知道此刻到底该做什么。

**实现范围**：

1. 固定首页叙事：`长期目标 → 当前阶段 → 当前里程碑 → 本周要达成什么 → 今天唯一下一步`。
2. 明确每日优先规则：有到期错题时，首页主行动先进入“今日复盘”；当天原任务显示为复盘后的下一项，不隐藏、不丢失。
3. “开始这一项”必须进入真实对象：课时进入课程学习桌；练习任务进入练习；错题任务进入到期队列；无对象任务进入聚焦任务详情并显示可选行动。
4. 任务聚焦视图说明：为什么做（阶段/里程碑）、做到什么算完成（退出标准或可观察结果）、做完去哪（课程、练习、错题或理解记录）。缺少数据时明确待补充，不伪造内容。
5. 保持“任务完成 = 证据；里程碑完成 = 用户复盘确认”的现有边界。

**不做**：重做计划数据模型、自动判定掌握、让 AI 自动改写每天任务。

**验收**：

- 首页两步内到达具体学习对象；
- 任一今日任务能解释服务的阶段与里程碑，或明确尚未归属；
- 有到期错题时，不必先进入筛选页就能完成一次复盘；
- 无目标、无任务用户只看见首周启动这一条主行动。

**进入阶段 2 条件**：三类用户均能说出“现在做什么、为什么做、做完去哪”，无 P0/P1 主线断点。

### 阶段 2：重构为统一的学习资源系统

**用户问题**：用户不清楚“我用什么学、学到哪里、返回后下一步是什么”。

**实现范围**：

1. 将“资料”用户文案和入口统一为“学习资源”，保留 `/materials` 路由兼容；聚合课程、外部课程链接、附件和阅读/笔记资源。
2. 每个资源显示来源、服务的任务/里程碑、当前状态、已学位置或进度文本、下一步；第一版复用现有模型，避免迁移。
3. 从今日任务进入资源；未关联资源时，任务现场只提供“添加课程或资料”这一条行动，并保留首课自动关联。
4. 外部课程始终新标签页打开，不嵌入、不代理、不检测第三方播放进度；用户回到 C6 后以“结束本次学习”明确记录进度、自评、卡点和下一步。
5. 不可解析文件显示“可打开但不能被 AI 检索”的用途、原因与“补充关键摘录”的行动，不把解析失败伪装成上传失败。

**不做**：视频托管、网页代理、第三方内容抓取、完整文档编辑器、重型 OCR/RAG。

**验收**：

- 用户一分钟内可添加 B 站或其他网课链接并关联今天任务；
- 用户可从任务进入资源，结束学习后保存进度与下一步；
- 上传成功但不可解析的文件仍可打开，并有明确的非 AI 使用路径；
- 不配置 AI 也能完成资源添加、学习、记录和回看。

**进入阶段 3 条件**：资源反馈中不再出现“链接打不开 / 不知如何关联任务 / 不知学到哪里”的 P0/P1。

### 阶段 3：将错题本收成每日复盘流程

**用户问题**：用户不需要理解 SM-2、筛选和批量管理，只需完成一次有效复盘。

**实现范围**：

1. 首页到期错题文案收成“今日有 N 道需要巩固 → 开始复习 → 预计时长”；筛选、导入、真题库、导出留在管理入口。
2. 一次只处理一道题：回忆/作答 → 答案与解析 → `仍不会 / 有点模糊 / 可以独立做` → 易错点或解题思路 → 可选确认知识点 → 下次复习。
3. 保留 `WrongQuestion` 的 SM-2 字段和内部映射，但前端不再要求理解 0–5 算法。一次复习只写一条幂等 `StudyEvidence`。
4. 复盘仍追加为带 `wrongQuestionId` 的 `StudyNote`（`error` / `method`），历史复盘在下一次回带；不为单次文本强行迁移字段。
5. 在复习现场提供已有知识点候选与用户确认式关联；不可靠时允许跳过，不能按题目文本自动绑定。

**不做**：公共题库、AI 批量判题、自动完成里程碑、删除或迁移历史错题。

**验收**：

- 用户从首页完成一次错题复习，不接触筛选页和算法术语；
- 每次复习可选留下错因或策略，下一次能回看；
- 用户确认关联后，知识点页可回看相关错题与反思；
- 来源、复习历史和学习证据不丢失，重复提交不会重复推进里程碑。

**进入阶段 4 条件**：桌面、手机的错题主路径均通过真实复现，连续一周无“复习后记录找不到 / 不知下一步”的 P1。

### 阶段 4：让个人知识库自动成长

**用户问题**：知识库不应是空图或手工维护关系的负担，而应让用户回看自己的理解演变。

**实现范围**：

1. 用户只需在课程、任务、练习或错题现场写：`我的理解`、`易错点`、`解题思路`；不要求前往知识图谱页建节点。
2. 系统依据来源任务节点、课程上下文和已有显式关联提供候选知识点；用户确认后才建立关系。AI 仅可生成候选，不能静默写入。
3. 节点详情只展示事实：关联理解、错题、资源、最近学习、下次回顾、未解决问题和正在推进的任务；不显示虚构总掌握度。
4. 知识图谱保留为浏览、回顾、定位工具；在首批 408 骨架验证前不扩展全科内容。

**不做**：自动生成全量知识网络、模型判定掌握、要求用户画关系、第二套笔记系统。

**验收**：

- 任一课程或错题记录都能留下个人理解并保留来源；
- 打开一个知识点时，能看出学过、错过、复习过什么及下一步；
- 不手动维护图谱，也能逐步拥有可用的个人知识网络；
- 多次“模糊/不会”只触发复盘或补强建议，不自动改变里程碑完成状态。

## 6. 功能状态、Beta 与暂缓清单

Beta 只用于“可体验、但不应成为关键学习判断依据”的能力：它必须在导航和功能现场说明边界、提供不用它的替代路径，并以真实使用证据决定转正或收缩。核心闭环（目标、计划、任务、课程、资源、错题、理解记录）不以 Beta 代替修复责任。

| 状态 | 功能 | 当前边界 | 转正或调整条件 |
|---|---|---|---|
| Beta | AI 出题练习 | 仅作补充练习，题目与解析需用户核对 | 真实使用中验证题目质量、等待时长、失败率与错题收录链路 |
| Beta | AI 工作区、AI 周复盘 | 只提出建议与草稿，用户确认后才改变计划 | 证明速度、可理解性与“建议 → 确认 → 执行”完成率稳定 |
| Beta | AI 技能、知识图谱、院校情报 | 高级流程、知识关联浏览、外部数据参考 | 累积真实使用证据；院校信息始终以官方文件为准 |
| 暂停 | 排行榜与社区 | 不进入普通导航，不与个人学习主线竞争 | 核心闭环稳定后再评估是否恢复 |

| 继续投入 | 仅维护、不扩展 | 明确暂缓 |
|---|---|---|
| 目标、路线、周计划、今日主线 | 院校信息、番茄钟、周报、技能 | 视频托管/下载/转码、社群与排行 |
| 学习资源与外链学习记录 | 泛资料搜索、低频设置、通用聊天历史 | 自由拖拽工作台、完整白板/手写笔记 |
| 错题复盘、个人理解、知识节点 | 现有练习功能 | 全科知识大图、重型 OCR/RAG |
| AI 规划、复盘与调整草案 | 批量导入和导出能力 | 高频即时题解、自动出题、自动判定掌握 |

“仅维护”表示保持入口可用、修复 P0/P1，不新增能力；“暂缓”表示不纳入 V1 验收，也不以其替代核心闭环进度。

## 7. 每阶段的交付与发布门槛

1. 开工前使用 [task-template.md](./task-template.md) 写清单一用户问题、范围和非目标；
2. 每次修改至少覆盖一个真实用户路径、一个空状态或失败状态，以及手机视口；
3. 涉及私有 API、数据关联、离线队列、AI 写入或 Schema 时，补充鉴权、幂等、迁移或安全检查；
4. 发布候选通过 `npx tsc --noEmit`、`npm run lint`、`npm run build`、相关 Playwright；跨学习闭环改动运行完整 `npx playwright test`；
5. 用户可见修复同步更新 `src/lib/changelog.ts` 与 `PROJECT_STATUS.md`；
6. 发布后将真实结果补回反馈台账和 `usage-notes.md`，再决定是否进入下一阶段。

## 8. 下一次开工的具体目标

### 迭代 0.5：三条主路径的短验收

不再建设反馈台本身。使用独立测试数据完成新手、正常用户、积累用户各一条路径，并把结论回填到台账：

1. 新手：首页 → 首周探索 → 第一项任务；
2. 正常用户：首页 → 今日任务 → 课程或学习资源 → 结束学习 → 回首页；
3. 积累用户：首页 → 今日复盘 → 留下错因或方法 → 知识点回看 → 原题。

若没有 P0，立即进入阶段 1；已确认的 FB-001（今日优先级）和 FB-004（首屏拥挤）不再等待额外方案，作为阶段 1 的输入。

### 迭代 1：今日唯一主线

第一项代码改动只解决“我现在该做什么”：有到期错题时先进入今日复盘，其他任务显示为后续下一项；任何主按钮都进入真实学习对象；任务现场补齐“为什么做 / 做到什么 / 做完去哪”。完成这一迭代后，再开始统一学习资源（阶段 2），不并行扩展低频工具或 AI 问答。
